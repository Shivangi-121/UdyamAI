# UdyamAI Demo Guide

This guide demonstrates the checked-in prototype without implying that drafts or
recommendations trigger real-world actions.

## Start the demo

1. Follow the backend and frontend setup in the root [README](../README.md).
2. From `backend`, initialize or refresh only the sample merchants:

   ```powershell
   python -m app.seed --reset-demo
   ```

   The reset replaces `coconut` and `kirana` only when they are marked as demo
   merchants. It preserves the personal merchant and its records.
3. Start the API and static frontend, then open the frontend URL in a browser.
4. Explore the browser-local experience first, or connect from **Settings** using
   one of the development merchant tokens in `backend/.env.example`. Demo
   merchants are read-only. Do not expose development tokens outside a local
   demonstration.

## Suggested walkthrough

### 1. Review the business overview

- Open **Home** and compare the two demo merchants from **Settings**.
- Point out that totals are based on recorded sample transactions, not forecasts.
- Explain that a gross-profit figure is shown only when cost-of-goods data is
  available and does not subtract operating expenses.

### 2. Inspect stock and insights

- Open **Stock** and review product quantities.
- Open **Insights** to see rules-based findings from recorded sales and stock.
- Explain that replenishment estimates require sufficient recent sales history,
  a stock count, and supplier lead-time information.

### 3. Compare a hypothetical scenario

- Open **Business Twin**, choose a product or enter values, and adjust demand,
  inventory, price, cost, discount, or period.
- Save a valid scenario. Try an invalid or out-of-range value to show that invalid
  inputs are rejected instead of silently producing a clamped estimate.
- Emphasize that the result is an assumption-based scenario, not a prediction.

### 4. Ask a question

- Ask a fact-based question such as which product sold the most, then ask a
  follow-up such as “check its stock.”
- Explain that the assistant can use bounded follow-up context in the current
  session. Recorded-data facts are grounded in available records; open-ended
  recommendations may be generated by rules or the optional configured LLM.
- The persistent voice control is available on every page. Speech input depends
  on browser support and microphone permission; typed questions are always the
  fallback. The assistant answers questions but does not execute business actions.

### 5. Show drafts and checklists

- In **Campaign Studio**, generate or edit a promotion and save it as a draft.
- In **Autopilot**, create or review a task checklist.
- State clearly that campaigns are not sent and tasks do not place orders or make
  external changes.

## Reset and repeat

Run `python -m app.seed --reset-demo` from `backend` to recreate the sample data,
campaign drafts, scenarios, action checklists, and derived insights. The command
does not reset browser-local data. Clear the browser's local storage separately
if the local-only workspace should also be reset.

## Demo environment limitations

- The optional LLM requires backend configuration and network access to the
  selected OpenAI-compatible provider. Without it, deterministic demo responses
  are used.
- Browser speech recognition and speech synthesis vary by browser, operating
  system, and installed language packs.
- The demo contains no payment, ordering, SMS, WhatsApp, or social publishing
  integration.
- The backend's bundled tokens and process-local rate limits are for local
  development, not production deployment.
